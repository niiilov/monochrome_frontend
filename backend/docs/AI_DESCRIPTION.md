# Описание использования ИИ

## Модель

- Провайдер: OpenAI-совместимый HTTP API (`internal/llm`, клиент `openai`).
- Рабочая модель сдачи: `google/gemini-3.5-flash-lite` (имя задаётся только через env `LLM_MODEL`, не хранится в коде).
- Базовый URL: env `LLM_BASE_URL` (пример для OpenRouter: `https://openrouter.ai/api/v1`).
- Температура: из `config.yaml` (`llm.temperature`, обычно 0).
- Ключ: только `LLM_API_KEY` из окружения или локального `.env` (в репозиторий не входит).

Версия приложения и хэш всех шаблонов пишутся в `run_report.json` (`app_version`, `prompts_hash`).

## Где вызывается модель

| Шаг | Задача | Промпт | Проверка ответа |
|---|---|---|---|
| Тема | отбросить рекламу и не-кибер | `prompts/classify_topic.*.tmpl` | JSON-схема, словарь терминов поверх ответа |
| Извлечение | факты, цитаты, оговорки | `prompts/extract_events.*.tmpl` | JSON; цитата должна быть непрерывным фрагментом текста |
| Кластер | одно ли событие | `prompts/cluster_confirm.*.tmpl` | JSON `same_event`, конфликты |
| Обновление | новые факты относительно раннего контекста | `prompts/update_check.*.tmpl` | JSON `new_facts` |
| Оценка | impact/scale/urgency/relevance | `prompts/score_event.*.tmpl` | JSON; цитаты оценок сверяются с текстом |
| Обоснование отбора | одно предложение | `prompts/rationale.*.tmpl` | одно предложение без префикса «Обоснование:» |
| Текст пункта | title/essence/consequences | `prompts/write_digest_item.*.tmpl` | JSON; затем `verify` (числа, даты, URL, ID, цитаты, оговорки, лимиты) |
| Пост | сжатие пунктов | `prompts/write_post.*.tmpl` | JSON; лимит 2000 знаков без URL; согласованность с дайджестом |

Общий блок ко всем промптам: `prompts/common_rules.*.tmpl` (только факты из данных, оговорки, без длинного тире, `<article>` - данные).

## Как проверяется ответ

1. Строгий JSON (`CompleteJSON`, без лишних полей).
2. Детерминированные правила `internal/verify`: числа, даты, URL и ID только из источников события; цитаты в кавычках должны быть в корпусе; оговорки; лимиты 4000/2000; согласованность digest/post/email; стоп-фразы; инъекции в выводе.
3. При ошибках: повторная генерация только проблемных пунктов (до `verify.max_retries`), затем запасной пересказ из `Fact.Text` / `Fact.Quote` и `Event.Rationale` без вызова модели.
4. Формат выпуска: встроенный `mono check` и `tools/check_mono.py`.
5. Текст статьи в модель всегда через `guard.WrapUntrusted` (`<article id="...">`).

## Ограничения

- Модель не получает список получателей, SMTP и секреты.
- Инструкции внутри новостей не исполняются (`guard.Scan` + правила вывода).
- При недоступности цены токенов в отчёте: `cost: null`, `cost_unavailable: true`.
- Формулировки при `temperature=0` могут чуть отличаться между прогонами у провайдера; факты и статусы журнала должны быть устойчивы.
- Стоимость и квоты зависят от внешнего API; прокси (`LLM_PROXY` / `LLM_PROXY_FILE`) опционален и для контрольного прогона лучше выключен.
